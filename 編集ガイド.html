JOSEKI MOCHIBE

自分で直すための地図

定石モチベは HTML 1枚でできています。インストールもビルドも要りません。 ファイルを開いて、直して、保存して、ブラウザを更新する。それだけで反映されます。

はじめかた ファイルの地図 やりたいこと別 壊したときは 戻せるように 用語

はじめかた

  1. ファイルを開く VS Code を開いて、ファイル → フォルダーを開く で デスクトップ\joseki-mochibe を選ぶ。左の一覧から index.html をクリック。
  2. 直して保存する 書き換えたら Ctrl+S。
  3. ブラウザで見る エクスプローラーで index.html をダブルクリックするとブラウザで開きます。 以降は保存するたびに、そのタブで Ctrl+R（更新）を押せば反映されます。
進捗が残らないときがあります。 ファイルを直接開くと、ブラウザによっては「解いた数」の保存が効きません。 見た目と動きの確認はできるので、編集中はこれで十分です。 実際の練習は公開版のURLのほうを使ってください。壊れているわけではありません。

モチに出会う条件を変える

const FORMS=

モチは★のたまり具合ではなく、その系統の定石を何本おぼえたかで増えます。 そこを決めているのが req です。

  {n:"うさぎもち", req:{tag:"うさぎ", need:6},
   w:116, h:88, parts:["rabbit"],
   note:"兎定石のうさぎ。白の縦取りに黒c5をおぼえた姿。",
   chara:"耳がいい。相手の打つ音でつぎの手を先に聞きとる。"},
req:{tag:"うさぎ", need:6}
うさぎ系の定石を6本おぼえたら出会える。 tag に使えるのは うさぎ／とら／ねこ／うし／ねずみ／ローズ。
req:{kinds:4}
上のような「系統のモチ」を4種るいそろえたら出会える。
req:null
さいしょからいる（こもち）。

「おぼえた」の中身は、その定石で出題されるところを全部正解したことです。 演出を全部見たいときは need をぜんぶ 1 にすると すぐ最後まで進みます。確認できたら元に戻してください。

need は、その系統に入っている定石の本数より多くしないでください。 たとえば ねずみ系は3本しか収録がないので、need:6 にすると 一生出会えないモチになります。系統ごとの本数は、 アプリの「定石とうろく → ＋新規定石 → えらぶ」のけいとうボタンで見られます。

モチの見た目を変える

FORMS / buildMochi

モチは画像ではなく、その場で線を引いて描いています。だから寸法もパーツも数字で変えられます。 変更は3段階あって、下にいくほど手間がかかります。

① 大きさ・ずんぐり具合を変える いちばん簡単

FORMS の w が横幅、h が高さです。

  {n:"うさぎもち", need:5,   w:116,h:88,  parts:["rabbit"],
                        ↑横   ↑高さ    ↑つけるパーツ

w を大きく h を小さくすると、ずんぐりします。逆なら細長くなります。 数字はだいたい w が 100〜150、h が 70〜115 の範囲に収めてください。

② パーツを入れ替える

parts に名前を並べると、その部品が生えます。用意してあるのは13種類です。

名前なにが出るか
rabbit長いうさぎ耳
mouse丸いねずみ耳
tiger三角のとら耳
cowうしの角
tailくるんとしたしっぽ
wings小さな羽
crown王冠
flower花の冠
mikan頭のみかん
stack二段重ねの体になる
spots体のぶち模様
stripes体のしま模様
rainbow体の虹しま

組み合わせは自由です。parts:["rabbit","crown","stripes"] のようにすれば、 王冠をかぶったしま模様のうさぎもちになります。

③ 新しいパーツを作る

buildMochi() に、パーツ1つにつき if のかたまりが1つ書いてあります。 真似して足せば新しいパーツができます。ねこ耳を足す例です。

  if(P.includes("cat"))
    [-1,1].forEach(sg=>mk(g,"path",{
      d:`M ${CX+sg*18} ${headTop+6} L ${CX+sg*30} ${headTop-22}
         L ${CX+sg*42} ${headTop+4} Z`,
      fill:skin, stroke:OL,"stroke-width":OW,"stroke-linejoin":"round"}));

あとは FORMS のどれかに parts:["cat"] と書けば出ます。

どこに書くかで前後が変わります。 buildMochi() は上から順に描いていて、あとに書いたものが手前に来ます。 耳や角は 体を描く前（rabbit や tiger が並んでいるあたり）に置くと 体の後ろに回り、生えているように見えます。頭の上にのせたいもの（王冠など）は体より後ろに書きます。
座標の読みかた。モチは横200・縦226のマス目の上に描いています。 CX＝真ん中（100）、BY＝足もと（224）、headTop＝頭のてっぺん。 y は下にいくほど大きいので、headTop-22 は「頭より22ぶん上」という意味です。 [-1,1].forEach(sg=>...) は左右2つぶんをまとめて描く書き方で、 sg が -1 なら左、1 なら右になります。
用意してある部品。skin＝モチの地の色、OL＝縁の色、 OW＝縁の太さ。この3つを使っておけば、登場演出のシルエット（真っ白な影）にも 自動で正しく出ます。自分で色を直書きすると、影のときも色がついてしまいます。

顔つきを変える

buildMochi の最後

buildMochi() の最後、if(sil) return; より下が顔です。 ここは全部の姿で共通なので、直すと8体ぜんぶの顔が変わります。

  const fy=headTop+headH*0.40;        ← 顔の高さ。0.40 を小さくすると顔が上がる
  mk(g,"ellipse",{cx:CX+sg*16, cy:fy, rx:5, ry:6.4, ...});   ← 目。rx/ry で大きさ
  mk(g,"ellipse",{... rx:8, ry:5, fill:"#FF9FC8", opacity:.6});  ← ほっぺ
  mk(g,"path",{d:`M ${CX-8} ${fy+13} Q ${CX} ${fy+20} ${CX+8} ${fy+13}`, ...});  ← 口

口の fy+20 を fy+8 にすると、笑った口が真一文字に近づきます。 目の ry を大きくすると、たれ目っぽくなります。

モチには2種類あります。

けいとうのモチ
うさぎもち・とらもち など9体。const FORMS= に書いてあります。

壊したときは

真っ白な画面が出たら、それは文法のまちがいです。こわくありません。

  1. F12 を押す ブラウザの開発ツールが開きます。Console タブを選んでください。
  2. 赤い行を読む Uncaught SyntaxError: ... のうしろに index.html:842 のような 数字が出ます。その行のあたりがまちがっています。
  3. その行と、そのすぐ上の行を見る たいてい原因は次の3つです。
よくある原因見分けかた
全角日本語入力のまま ， ” （ を打っている。 半角の , " ( に直す
閉じ忘れ" } ] ) のどれかが足りない。 VS Code はカーソルを括弧に合わせると対になる括弧を光らせます
囲み忘れ日本語は必ず " で囲みます。 n:ローズ定石 ではなく n:"ローズ定石"
行の終わりのカンマ。 { } を並べるときは、あいだに , が要ります。 いちばん最後の { } のうしろは、あってもなくても動きます。
ブラウザの confirm() と alert() は使わないこと。 公開版は「サンドボックス」という制限つきの枠の中で動いていて、 その中では confirm() はダイアログを出さないまま、黙って「いいえ」を返します。 エラーも出ないので、ボタンが何も反応しないように見えます。実際これで 「登録から外す」「おまかせで配る」「きろくをリセット」の3つが動かなくなりました。 いまは自前の ask() に置きかえてあるので、 たしかめが要る場面ではそちらを使ってください。

戻せるようにしておく

これがあるだけで、思いきって触れるようになります。

  • いちばん簡単 — 触る前に index.html をコピーして、 同じフォルダに index_backup.html を作っておく。 だめだったら消して、名前を戻すだけ。
  • ちゃんとやるなら — GitHub Desktop でこのフォルダを管理すると、 変更した行が色分けで見え、いつでも「変更を破棄」で戻せます。 何をどう変えたかが残るので、あとから自分で読み返せるのが大きいです。
